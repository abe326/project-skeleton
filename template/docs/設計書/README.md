# docs/設計書/ — 設計の正本

プロダクトの設計・方針を示す恒久ドキュメント。**詳細仕様はコードが正本**で、設計書は概要・方針（基本設計レベル）にとどめる。スリムに保つ（目安 20 本以内）。

## 索引

| パス | 内容 |
|:--|:--|
| `01-overview.md` | 何を作るか。目的・利用者・スコープ・非スコープ・用語 |
| `02-architecture.md` | どう作るか。構成・技術スタック・データの流れ・境界 |
| `decisions/` | ADR（1 判断 1 ファイル）。索引は `decisions/README.md`、型は `decisions/ADR-000-テンプレート.md` |

## 変えたもの → 一緒に直す正本

設計書のどれかを変えたら、同じ作業で次を見る。空欄はプロジェクトで埋める。

| 変えたもの | 一緒に直す正本 | 備考 |
|:--|:--|:--|
| `01-overview.md` の目的・スコープ | `docs/プロジェクト概要.html` の「1. 目的・背景」（`update-overview` スキル） | |
| `02-architecture.md` の構成図・環境 | `docs/プロジェクト概要.html` の「5. 構成図と環境の入口」、`環境情報.md`（`update-env-info` スキル） | |
| `decisions/` に ADR を追加 | `decisions/README.md` の索引、`docs/プロジェクト概要.html` の「直近の決定」 | |
| 技術スタック | `CLAUDE.md` §5 | |
| 用語 | `CLAUDE.md` §6 | |
| | | |

## 書き方

- 時点の状態ではなく**決定した事実**を書く。「検討中」はタスク md へ
- 実装と食い違ったら、まず設計書側で「どちらが正か」を確定してから下流を合わせる
- 秘密（URL・ID・パスワード・鍵）は書かない。環境の実値は `環境情報.md`
