## 0. 位置づけ

「変更がどう本番に届き、どう戻るか」の方針。手順の本文は `runbook/`（1 操作 1 ファイル）に置き、本書は方針と索引だけを持つ。

`未決`・`提案` の項目を根拠に「方針に反する」と指摘しない。`決定` に実装が反していれば実装側を直す（`04-設計原則.md` §3）。

## 3. 変更の流れ

起票 → ブランチ → 実装 → ゲート（06 §5）→ レビュー（06 §4）→ マージ → デプロイ（§5）。

| 項目 | 規約 | 状態 |
|:--|:--|:--|
| 起票 | タスク md（`task` スキル）。ID をブランチ・コミット・PR に書く | 決定 |
| ブランチ | | |
| コミット | | |
| PR | | |
| CHANGELOG | `CHANGELOG.md`（ルート）。利用者に見える変更だけ | 決定 |

（例）`ブランチ | <タスクID>/<短い英語>。main へ直接 push しない | 提案`
