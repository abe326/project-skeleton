# project-skeleton 機能一覧

> 対象: v1.5.0 ／ 人向けの要約は `docs/プロダクト概要.html` の「機能一覧」。ここは全機能の詳細（いつ動くか・利用者の操作・担当ファイル）
> パスは、スケルトンのリポ（`scripts/init.py` など）と、生成した作業フォルダ（`.claude/…`・`docs/…`）の両方がある。生成先のものは作業フォルダからの相対

**読み方**
- **いつ動くか**: 「自動」は hook・スクリプトが動くもの。「Claude」は Claude Code が skill や CLAUDE.md を読んで自分から行うもの。「依頼」は利用者が頼んだときに動くもの
- **利用者の操作**: 「不要」なら、何も指示しなくても働く。このスケルトンは、AI に明示的に指示できない人でも「不要」で済む範囲を広げることを目指している
- ★ は v1.5.0 で入れたもの

## 1. 生成と追従

| 機能 | いつ動くか | 利用者の操作 | 担当 |
|---|---|---|---|
| 作業フォルダの生成 | 依頼 | 「○○のプロジェクトを作って」。足りないのは名前だけ聞かれる | `SKILL.md`（new-project）・`scripts/init.py` |
| 生成の仕上げ（タスク一覧の初期化・git init と初回コミット・構成の検査） | 生成の直後に自動 | 不要 | `scripts/init.py` |
| 既存フォルダへの適用 | 依頼 | 「既存の○○にスケルトンを入れて」 | `init.py --merge` |
| ★ 生成時の記録（版・コミット・生成時の値・入れたファイルの元の内容の sha） | 生成・適用のたびに自動 | 不要 | `.claude/skeleton.json`（init.py が書く） |
| ★ ずれの検知（スケルトンに新しい版が出たことを知らせる） | セッション開始時に自動 | 不要。Claude が区切りで 1 行提案する | `.claude/hooks/skeleton_drift.py`・`session_context.sh` |
| ★ 新しい版への追従（手を入れていないファイルは自動で更新・前の中身は退避） | 提案を了承したとき | 「はい」と答える | `init.py --merge`・`.work/_bk/YYYYMMDD_skeleton-vX.Y.Z/` |
| ★ 3-way merge（手を入れた仕組みと CLAUDE.md・概要 HTML は、案件の変更を残して混ぜる） | 追従のとき自動 | 不要。衝突したものだけ Claude が相談する | `init.py`（`git merge-file`） |
| ★ 衝突・内容の案（書かずに新しい版を置き、Claude が取り込む） | 追従のとき自動 | 迷うところだけ答える | `.work/一時/YYYYMMDD_skeleton-update/`・`init.py --merge --resolved` |
| ★ 無くなった仕組みの片付け・案件が消したファイルを作り直さない | 追従のとき自動 | 不要 | `init.py` |
| ★ 記録の無い案件への後付け（CLAUDE.md の刻印とスケルトンの履歴から元の内容を作り直す） | 初めての追従で自動 | 初回だけ表示名を答える | `init.py` |
| ★ 版ごとの定型の移行（移動・設定への追加・置き換え） | 追従のとき自動（冪等） | 不要 | `scripts/migrations.json` |
| 判断が要る移行手順の提示 | 追従のとき自動（対象の版の分だけ出す） | Claude が読んで進める。迷うところだけ答える | `CHANGELOG.md` の「既存プロジェクトへの適用」 |
| ★ 既存フォルダを読んで下書き（概要・現在地・案件情報・環境情報・project.json） | 初めて入れたとき Claude | 下書きの誤りを直すだけ | `.claude/skills/draft-from-existing/` |
| 直したものをスケルトンへ返す | Claude が台帳に書く／スケルトン側で集める | 不要（スケルトンの持ち主が取り込む） | `docs/ハーネス台帳.md` の「返す」列・`scripts/collect_returns.py` |

## 2. タスク・課題

| 機能 | いつ動くか | 利用者の操作 | 担当 |
|---|---|---|---|
| 起票（ID は自動採番。タスク 9 節・課題 7 節の雛形） | Claude・依頼 | 「タスクにして」「課題にして」、または不要（拾ったものを Claude が起票） | `task` スキル・`docs/案件/01_タスク管理/new.py` |
| その場で決まったことの記録（起票してすぐ閉じる） | Claude | 不要 | `new.py … --decided "…" --to …` |
| 課題のクローズ（決定と落ち先が無ければ閉じない） | Claude・依頼 | 「決着した」 | `close.py` |
| ★ 完了条件の警告（チェックの無い条件が残っていれば知らせる。閉じるのは止めない） | タスクを閉じるとき自動 | 不要 | `close.py`・タスク md の `## 完了条件` |
| 一覧（HTML）と概要 HTML の自動欄（決めてほしいこと・次の節目・直近の決定・件数） | 起票・クローズのたびに自動 | ブラウザで `index.html` を開く | `build.py`・`index.html`・`data.js` |
| 画面の進捗 | 依頼 | 「画面を足して」 | `screen.py`・`screens/` |

## 3. 記録と拾いもの

| 機能 | いつ動くか | 利用者の操作 | 担当 |
|---|---|---|---|
| 依頼文の手がかり（あとで・決めた・未定…）を記録 | 依頼を送るたびに自動 | 不要 | `.claude/hooks/pickup_cue.py`（UserPromptSubmit） |
| 区切りでの拾い直し（落ち先の無いものがあれば 1 回だけ促す） | 応答の終わりに自動 | 不要 | `.claude/hooks/pickup_check.py`（Stop） |
| 決定・未決・あとでやることを置き場へ落とす | Claude（区切り） | 不要 | `pickup` スキル |
| 打合せ記録の落ち先（各行に → 反映済／ID） | 打合せ記録を保存したとき自動で促す | 「打合せを記録して」 | `design_docs_reminder.py`・`docs/案件/02_打合せ/` |
| 作業ログ（出来事の時系列を正本から生成） | 応答の終わりに自動 | 不要 | `.claude/hooks/work_log.sh`・`scripts/work_log.py` |
| 落ち先の検査（落ち先なし・書式・ID 不在・期限切れ） | セッション開始時に件数・依頼で一覧 | 不要 | `scripts/check_drops.py` |
| 相手に確認したいことの一覧 | Claude | 不要 | `docs/案件/確認依頼一覧.md` |

|---|---|---|---|
| 概要 1 本で始める・要るときに 1 本ずつ足す | Claude が候補を出す | 足すかどうかを答える | `scripts/add_doc.py`・`docs/設計書/template/` |
| 変更に合わせた設計書の候補（影響マップ） | ファイルを書いたとき自動 | 不要 | `design_docs_reminder.py`・`impact_map.py`・`docs/設計書/README.md` の表 |
| まだ無い文書に関わる変更の知らせ | ファイルを書いたとき自動 | 足すかどうかを答える | `impact_map.addable_docs()` |

## 5. 置き場と秘密

| 機能 | いつ動くか | 利用者の操作 | 担当 |
|---|---|---|---|
| 作業の前に紐づくタスクを決める | Claude（作業の前） | 曖昧なときだけ答える | `work-placement` スキル |
| 一時的な出力は日付のフォルダへ | Claude | 不要 | `scratch` スキル |
| 置き場のガード（決めた置き場の外への書き込みを止める） | ファイルを書く前に自動 | 不要 | `.claude/hooks/work_area_guard.py`（PreToolUse） |
| 案件で決まった置き場を通す | 案件が書いたとき | 不要（承認だけ） | `.claude/project.json` の `work_area_allow` |
| 秘密は環境情報と .env にだけ | Claude・検査 | 不要 | `.claude/rules/secrets.md`・`check_skeleton.py --secrets` |
| 環境・関係者・日程の正本の更新 | Claude（変化があったとき） | 不要 | `update-env-info` スキル・`環境情報.md`・`案件情報.md` |

## 止めるもの・止めないもの

機械が止めるのは 3 つだけ: 秘密を共有物に書いたとき、決めた置き場の外にファイルを作ったとき、拾ったものがどこにも落ちていないとき（課題は決定と落ち先が無ければ閉じない）。
空欄・未記入・未決の多さ、完了条件のチェック漏れ、スケルトンの版の遅れは、知らせるだけで止めない。
